**XProxy** é um host de servidores proxy do ecossistema NewLife. Um único processo hospeda vários serviços `ProxyBase`, incluindo proxy reverso NAT, proxy direto HTTP e proxy reverso HTTP. Ele usa a pilha de rede de alto desempenho NewLife.Net, instala-se como serviço do Windows ou daemon do Linux via NewLife.Agent, publica com NativeAOT e localiza as mensagens de interface via NewLife.Core.

## Início rápido

Requer o SDK do .NET 10.

```bash
git clone https://github.com/NewLifeX/XProxy.git
cd XProxy
dotnet run --project XProxy
```

Na primeira execução, o XProxy cria `Config/XProxy.config` e inicia os proxies de demonstração:

| Demonstração | Provedor | Escuta | Destino |
| --- | --- | --- | --- |
| Demo1 | NAT | `tcp://0.0.0.0:3388` | `tcp://localhost:3389` |
| Demo2 | Http | `tcp://0.0.0.0:1080` | Proxy direto HTTP (autenticação Basic `user=` / `pass=newlife`) |
| Demo3 | HttpIp | `tcp://0.0.0.0:8080` | `tcp://www.newlifex.com:80` |
| Demo4 | HttpReverse | `tcp://0.0.0.0:8081` | `tcp://www.newlifex.com:80` |

O console interativo permite instalar o programa como serviço do Windows (`-i`) ou simular a execução (`-run`). A instalação exige privilégios de administrador.

## Recursos

- **Proxy reverso NAT**: encaminha qualquer porta TCP ou UDP para um servidor de destino, com portas múltiplas e validação de prefixo opcionais.
- **Proxy direto HTTP**: aceita requisições em forma absoluta (`GET http://...` e `GET https://...`), suporta autenticação Basic, remove cabeçalhos exclusivos do proxy e encaminha para destinos HTTP ou HTTPS conforme o esquema.
- **Proxy reverso HTTP**: reescreve `Host` e `Referer` para sites publicados em modo reverso.
- **Saída com vários IPs**: `HttpIp` escolhe o endereço local de origem nos modos `any`, `round`, `random` ou `origin`.
- **Hospedagem como serviço**: executa como serviço do Windows, unidade systemd ou aplicação de console via NewLife.Agent.
- **Rastreamento distribuído**: envia spans ao Stardust quando um servidor está configurado (builds JIT; desativado no NativeAOT).
- **Configuração a quente**: recarrega `Config/XProxy.config` em até dez segundos.
- **NativeAOT e localização**: publica como executável nativo autocontido; as mensagens seguem o idioma selecionado.

## Configuração

`Config/XProxy.config` é gerado na primeira execução:

```xml
<Setting>
  <Debug>true</Debug>
  <Items>
    <ProxyItem Name="Web" Provider="HttpReverse" Enable="true"
               Local="tcp://0.0.0.0:8081" Remote="tcp://www.newlifex.com:80" Config="" />
  </Items>
  <Language>pt</Language>
</Setting>
```

`Provider` aceita `NAT`, `Http`, `HttpIp` e `HttpReverse`. `Config` depende do provedor:

| Provedor | Chaves de configuração |
| --- | --- |
| `NAT` | `Ports` (número de portas consecutivas), `Prefix` (validação de prefixo hexadecimal) |
| `Http` | `user`, `pass` e `realm` para autenticação Basic do proxy |
| `HttpIp` | `IpMode` = `Any` / `Round` / `Random` / `Origin` |

## NativeAOT

```bash
# linha de comando
dotnet publish XProxy/XProxy.csproj -c Release -r win-x64 -p:PublishAot=true

# ou o perfil de publicação incluído
dotnet publish XProxy/XProxy.csproj -c Release -p:PublishProfile=win-x64-aot
```

O executável publicado inclui o runtime do .NET e não exige instalação separada. Encaminhamento, configuração e hospedagem como serviço funcionam no NativeAOT. O rastreamento Stardust é desativado porque depende de reflexão dinâmica; o XProxy exibe um aviso ao iniciar sem rastreamento.

## Localização

- O inglês é o idioma de origem e de fallback. Os catálogos de chinês simplificado e tradicional estão em `XProxy/Locales`; os demais idiomas usam inglês, enquanto o NewLife.Core possui 31 idiomas integrados.
- Defina `Language` em `Config/XProxy.config` (por exemplo `en`, `zh-CN`, `zh-TW`) ou chame `NewLife.Setting.Current.Language`. Um valor vazio segue o idioma da interface do sistema.
- Adicione `XProxy/Locales/<culture>.yml` para ampliar o catálogo; as chaves são as strings originais em inglês.

## Compilação e testes

```bash
dotnet build XProxy.slnx -c Release
```

`Test` é um console de integração manual que envia requisições por um proxy HTTP em execução. Este repositório não possui projeto de testes automatizados; a construção de cabeçalhos HTTP é coberta pelos testes unitários do NewLife.Core.

O formato de versão é `3.2.yyyyMMdd`. A saída de compilação fica em `Bin/Server`.
