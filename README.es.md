**XProxy** es un host de servidores proxy del ecosistema NewLife. Un solo proceso aloja varios servicios `ProxyBase`, incluidos el proxy inverso NAT, el proxy directo HTTP y el proxy inverso HTTP. Se ejecuta sobre la pila de red de alto rendimiento NewLife.Net, se instala como servicio de Windows o demonio de Linux mediante NewLife.Agent, se publica con NativeAOT y localiza sus mensajes de interfaz mediante NewLife.Core.

## Inicio rápido

Requiere el SDK de .NET 10.

```bash
git clone https://github.com/NewLifeX/XProxy.git
cd XProxy
dotnet run --project XProxy
```

En la primera ejecución se crea `Config/XProxy.config` y se inician los proxies de demostración:

| Demo | Proveedor | Escucha | Destino |
| --- | --- | --- | --- |
| Demo1 | NAT | `tcp://0.0.0.0:3388` | `tcp://localhost:3389` |
| Demo2 | Http | `tcp://0.0.0.0:1080` | Proxy directo HTTP (autenticación Basic `user=` / `pass=newlife`) |
| Demo3 | HttpIp | `tcp://0.0.0.0:8080` | `tcp://www.newlifex.com:80` |
| Demo4 | HttpReverse | `tcp://0.0.0.0:8081` | `tcp://www.newlifex.com:80` |

La consola interactiva permite instalar el programa como servicio de Windows (`-i`) o simular su ejecución (`-run`). La instalación requiere privilegios de administrador.

## Características

- **Proxy inverso NAT**: reenvía cualquier puerto TCP o UDP a un servidor de destino, con puertos múltiples y validación de prefijo opcionales.
- **Proxy directo HTTP**: acepta solicitudes en forma absoluta (`GET http://...` y `GET https://...`), admite autenticación Basic, elimina las cabeceras propias del proxy y reenvía a destinos HTTP o HTTPS según el esquema.
- **Proxy inverso HTTP**: reescribe `Host` y `Referer` para sitios publicados en reversa.
- **Salida con varias IP**: `HttpIp` elige la dirección local de origen con los modos `any`, `round`, `random` u `origin`.
- **Alojamiento como servicio**: se ejecuta como servicio de Windows, unidad systemd o aplicación de consola mediante NewLife.Agent.
- **Trazabilidad distribuida**: envía trazas a Stardust cuando hay un servidor configurado (compilaciones JIT; desactivado con NativeAOT).
- **Configuración en caliente**: recarga `Config/XProxy.config` en menos de diez segundos.
- **NativeAOT y localización**: se publica como ejecutable nativo autocontenido y los mensajes siguen el idioma seleccionado.

## Configuración

`Config/XProxy.config` se genera en la primera ejecución:

```xml
<Setting>
  <Debug>true</Debug>
  <Items>
    <ProxyItem Name="Web" Provider="HttpReverse" Enable="true"
               Local="tcp://0.0.0.0:8081" Remote="tcp://www.newlifex.com:80" Config="" />
  </Items>
  <Language>es</Language>
</Setting>
```

`Provider` acepta `NAT`, `Http`, `HttpIp` y `HttpReverse`. `Config` depende del proveedor:

| Proveedor | Claves de configuración |
| --- | --- |
| `NAT` | `Ports` (número de puertos consecutivos), `Prefix` (prefijo hexadecimal de validación) |
| `Http` | `user`, `pass` y `realm` para la autenticación Basic del proxy |
| `HttpIp` | `IpMode` = `Any` / `Round` / `Random` / `Origin` |

## NativeAOT

```bash
# línea de comandos
dotnet publish XProxy/XProxy.csproj -c Release -r win-x64 -p:PublishAot=true

# o el perfil de publicación incluido
dotnet publish XProxy/XProxy.csproj -c Release -p:PublishProfile=win-x64-aot
```

El ejecutable publicado incluye el runtime de .NET y no necesita una instalación aparte. El reenvío, la configuración y el alojamiento como servicio funcionan con NativeAOT. La trazabilidad de Stardust se desactiva porque depende de reflexión dinámica; XProxy muestra un aviso al iniciar sin trazabilidad.

## Localización

- El inglés es el idioma de origen y de respaldo. Los catálogos chino simplificado y chino tradicional están en `XProxy/Locales`; los demás idiomas usan el inglés, mientras NewLife.Core incorpora 31 idiomas.
- Configure `Language` en `Config/XProxy.config` (por ejemplo `en`, `zh-CN`, `zh-TW`) o llame a `NewLife.Setting.Current.Language`. Un valor vacío sigue el idioma de la interfaz del sistema.
- Añada `XProxy/Locales/<culture>.yml` para ampliar el catálogo; las claves son las cadenas originales en inglés.

## Compilación y pruebas

```bash
dotnet build XProxy.slnx -c Release
```

`Test` es una consola de integración manual que envía solicitudes a través de un proxy HTTP en ejecución. Este repositorio no tiene proyecto de pruebas automatizadas; la construcción de cabeceras HTTP está cubierta por las pruebas unitarias de NewLife.Core.

El formato de versión es `3.2.yyyyMMdd`. La salida de compilación está en `Bin/Server`.
