**XProxy** هو مضيف لخوادم البروكسي ضمن منظومة NewLife. تستضيف العملية الواحدة عدة خدمات `ProxyBase`، بما في ذلك بروكسي NAT العكسي وبروكسي HTTP الأمامي وبروكسي HTTP العكسي. يعمل على حزمة الشبكة عالية الأداء NewLife.Net، ويثبّت كخدمة Windows أو خادم Linux عبر NewLife.Agent، وينشر باستخدام NativeAOT، ويعرّب رسائل الواجهة عبر NewLife.Core.

> ℹ️ قد تكون هذه الترجمة متأخرة؛ المرجع هو [English README](README.md).

## البدء السريع

يتطلب .NET 10 SDK.

```bash
git clone https://github.com/NewLifeX/XProxy.git
cd XProxy
dotnet run --project XProxy
```

ينشئ XProxy عند أول تشغيل الملف `Config/XProxy.config` ويبدأ خوادم البروكسي التجريبية:

| التجربة | المزوّد | الاستماع | الهدف |
| --- | --- | --- | --- |
| Demo1 | NAT | `tcp://0.0.0.0:3388` | `tcp://localhost:3389` |
| Demo2 | Http | `tcp://0.0.0.0:1080` | بروكسي HTTP أمامي (مصادقة Basic `user=` / `pass=newlife`) |
| Demo3 | HttpIp | `tcp://0.0.0.0:8080` | `tcp://www.newlifex.com:80` |
| Demo4 | HttpReverse | `tcp://0.0.0.0:8081` | `tcp://www.newlifex.com:80` |

تتيح وحدة التحكم التفاعلية تثبيت البرنامج كخدمة Windows (`-i`) أو محاكاة تشغيل الخدمة (`-run`). تتطلب عملية التثبيت صلاحيات المسؤول.

## الميزات

- **بروكسي NAT العكسي**: يمرّر أي منفذ TCP أو UDP إلى خادم هدف، مع دعم منافذ متعددة والتحقق من بادئة اختيارية.
- **بروكسي HTTP الأمامي**: يقبل الطلبات بالصيغة المطلقة (`GET http://...` و`GET https://...`)، ويدعم مصادقة Basic، ويحذف ترويسات البروكسي الخاصة، ويمرّر إلى أهداف HTTP أو HTTPS حسب المخطط.
- **بروكسي HTTP العكسي**: يعيد كتابة `Host` و`Referer` للمواقع المنشورة عكسيًا.
- **خروج بعناوين IP متعددة**: يختار `HttpIp` عنوان المصدر المحلي بالأوضاع `any` أو `round` أو `random` أو `origin`.
- **استضافة كخدمة**: يعمل كخدمة Windows أو وحدة systemd أو تطبيق وحدة تحكم عبر NewLife.Agent.
- **التتبع الموزع**: يرسل الآثار إلى Stardust عند تكوين خادم (إصدارات JIT؛ معطّل في NativeAOT).
- **تكوين فوري**: يعيد تحميل `Config/XProxy.config` خلال عشر ثوانٍ.
- **NativeAOT والتعريب**: يُنشر كملف تنفيذي أصلي مكتفٍ ذاتيًا؛ وتتبع الرسائل اللغة المحددة.

## التكوين

يُنشأ `Config/XProxy.config` عند أول تشغيل:

```xml
<Setting>
  <Debug>true</Debug>
  <Items>
    <ProxyItem Name="Web" Provider="HttpReverse" Enable="true"
               Local="tcp://0.0.0.0:8081" Remote="tcp://www.newlifex.com:80" Config="" />
  </Items>
  <Language>ar</Language>
</Setting>
```

يقبل `Provider` القيم `NAT` و`Http` و`HttpIp` و`HttpReverse`. ويعتمد `Config` على المزوّد:

| المزوّد | مفاتيح التكوين |
| --- | --- |
| `NAT` | `Ports` (عدد المنافذ المتتالية)، `Prefix` (التحقق من بادئة سداسية عشرية) |
| `Http` | `user` و`pass` و`realm` لمصادقة البروكسي Basic |
| `HttpIp` | `IpMode` = `Any` / `Round` / `Random` / `Origin` |

## NativeAOT

```bash
# سطر الأوامر
dotnet publish XProxy/XProxy.csproj -c Release -r win-x64 -p:PublishAot=true

# أو ملف تعريف النشر المضمّن
dotnet publish XProxy/XProxy.csproj -c Release -p:PublishProfile=win-x64-aot
```

يتضمن الملف المنشور وقت تشغيل .NET ولا يحتاج إلى تثبيت منفصل. يعمل تمرير البروكسي والتكوين واستضافة الخدمة في NativeAOT. يُعطّل تتبع Stardust لأنه يعتمد على انعكاس التجميعات الديناميكي؛ ويطبع XProxy رسالة عند التشغيل دون تتبع.

## التعريب

- الإنجليزية هي اللغة المصدر والاحتياطية. توجد قوائم الصينية المبسطة والتقليدية في `XProxy/Locales`؛ وتستخدم اللغات الأخرى الإنجليزية، بينما تتضمن NewLife.Core نفسها 31 لغة.
- اضبط `Language` في `Config/XProxy.config` (مثل `en` أو `zh-CN` أو `zh-TW`) أو استدعِ `NewLife.Setting.Current.Language`. القيمة الفارغة تتبع لغة واجهة نظام التشغيل.
- أضف `XProxy/Locales/<culture>.yml` لتوسيع القائمة؛ المفاتيح هي النصوص الإنجليزية الأصلية الدقيقة.

## البناء والاختبار

```bash
dotnet build XProxy.slnx -c Release
```

`Test` هو تطبيق وحدة تحكم للتكامل اليدوي يرسل الطلبات عبر بروكسي HTTP قيد التشغيل. لا يوجد في هذا المستودع مشروع اختبارات آلي؛ ويغطي اختبار الوحدة في NewLife.Core بناء ترويسات HTTP.

صيغة الإصدار هي `3.2.yyyyMMdd`، ومخرجات البناء في `Bin/Server`.
